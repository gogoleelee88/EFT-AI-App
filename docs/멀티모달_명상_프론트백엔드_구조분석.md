# 멀티모달 기반 사용자 맞춤형 AI 명상 서비스 — 프론트/백엔드 구조 분석

설계 문서 `멀티모달_AI명상_설계_2026-02-01.md` 기준으로 구현된 서비스의 **프론트엔드·백엔드 구조**를 정리한 문서입니다.

---

## 1. 진입 경로 및 라우팅

### 1.1 명상 플로우 (설계 문서 기준)

```
[감정 입력] → EFTStrictPage (SlideIntake)
    → POST /api/chat (strict_intake) → EFT 스크립트 응답
    → 사용자 선택: "EFT AR" | "명상"
         │
         └─ 명상 선택
              → /meditation/theme   (MeditationThemePage: 테마 선택)
              → /meditation/session (MeditationSessionPage: 세션 설계 + 음성 선택)
              → /meditation/run     (MeditationRunPage: 멀티모달 + Guidance API)
```

### 1.2 프론트엔드 라우트 (frontend/src/routes.tsx)

| 경로 | 컴포넌트 | 역할 |
|------|----------|------|
| `/eft-strict` | EFTStrictPage | 감정 수집(SlideIntake) → EFT/명상 선택 |
| `/meditation` | TriModalMeditation | 별도 명상 세션 (카메라+마이크+코칭, Guidance API 미사용) |
| `/meditation/theme` | MeditationThemePage | 테마 선택, strictIntake 전달 |
| `/meditation/session` | MeditationSessionPage | 세션 플랜·음성 선택, /meditation/run으로 state 전달 |
| `/meditation/run` | **MeditationRunPage** | **멀티모달 명상 메인** (Guidance API, face_data, Emergency, 피드백) |
| `/ar-box-breathing` | ARBoxBreathingPage | 박스 호흡 (Emergency에서 연결 가능) |

**설계 문서의 “단일 플로우”**는 **`/meditation/run`(MeditationRunPage)** 에서만 구현됩니다. `/meditation`(TriModalMeditation)은 별도 실험용 플로우입니다.

## 2. 프론트엔드 구조

### 2.1 디렉터리 맵 (명상·멀티모달 관련)

```
frontend/src/
├── pages/
│   ├── EFTStrictPage.tsx          # 진입: 감정 수집 → 명상/EFT 선택
│   ├── MeditationThemePage.tsx    # 테마 선택 (THEME_LIBRARY, getRecommendedThemeId)
│   ├── MeditationSessionPage.tsx  # 세션 설계 + voice_preference → /meditation/run
│   └── MeditationRunPage.tsx       # ★ 메인: 카메라·호흡·rPPG → face_data → Guidance API
│
├── components/meditation/
│   ├── EmergencyMeditationOverlay.tsx  # 긴급: 박스 호흡 4-4-4-4 + 연락처 + 명상 재개/종료
│   ├── TriModalMeditation.tsx          # 별도 명상 UI (Guidance API 미연동)
│   ├── BreathPacer.tsx, HUD.tsx, TopStats.tsx, SessionSummary.tsx, WeeklyReport.tsx
│   └── (기타)
│

│   └── meditation/
│       ├── mediaAccess.ts         # requestMediaOnce, stopMediaStream

│
├── signals/                       # 멀티모달 신호
│   ├── face.ts                    # MediaPipe FaceLandmarker, analyzeFace → FaceSignals
│   ├── SignalProcessor.ts         # Kalman, Calibration, Luminance, ProcessedFaceSignals
│   └── rppg.ts                    # extractHeartRate (녹색 채널·DFT·BPM), ROI 유틸
│

│   └── useBreathRate.ts           # 마이크 → 호흡/분 (breath_rate)
```

### 2.2 MeditationRunPage 데이터 흐름 (핵심)

```
location.state: strictIntake, session_plan, selected_theme_id, voice_preference
       │
       ├─► 첫 Chunk: generateGuidance({ intake, selected_theme_id, face_data: null })
       │
       ├─► 카메라 준비 후 (requestMediaOnce, initFaceLandmarker):
       │     • 400ms tick: analyzeFace(video) → SignalProcessor.process → faceSignalsToFaceData
       │     • useBreathRate(mediaStream) → breath_rate
       │     • 10Hz rPPG 버퍼 → 10초마다 extractHeartRate → heart_rate, heart_rate_confidence
       │     • getLuminanceFromVideo → luminance (Auto-Illumination)
       │     • setFaceData(face_data)  // tension_delta, baseline_tension, calibration_done 포함
       │
       ├─► Chunk 소진 시: generateGuidance({ ..., cursor: next_cursor, face_data: 최신 faceData })
       │
       ├─► 긴급: tension_delta > 0.2 또는 breath_rate > 25 지속 → emergencySuggestion 배너
       │         EmergencyMeditationOverlay (박스 호흡 + 1393/119/1577-0199)
       │
       └─► 종료 시: submitGuidanceFeedback({ guidance_id, best_moments, worst_moments, user_rating, ... })
```

### 2.3 API 호출 (명상 플로우)

| 용도 | 메서드 | URL | 호출처 |
|------|--------|-----|--------|
| 감정→EFT 스크립트 | POST | `/api/chat` | EFTStrictPage |
| 가이드 캡션 생성 | POST | `/api/guidance/generate` | guidanceService.generateGuidance (MeditationRunPage) |

## 3. 백엔드 구조

### 3.1 디렉터리 맵 (Guidance·명상 관련)

```
backend/
├── main.py                        # FastAPI 앱, include_router(guidance_router)
├── routers/
│   └── guidance_router.py         # POST /api/guidance/generate, /api/guidance/feedback
│
├── core/
│   ├── policy_engine.py           # decide_action, load_reference_scenario, THEME_LIBRARY
│   └── task_atom_chooser.py       # task_atom 추천 (Lite/Pro)
│
├── services/
│   ├── nlg_service.py             # render_scenario_chunk, face_data → face_desc, 호흡/심박 문구
│   ├── guidance_feedback_service.py  # append_feedback → guidance_feedback.jsonl
│   └── vllm_client.py             # Qwen 호출 (NLG 각색)
│
├── models/
│   └── chat_models.py             # StrictIntakeInput (face_data: Optional[Dict])
│
├── types/
│   └── guidance_schema.py         # GuidanceOutputState, GuidanceCursor, GuidanceFeedbackRequest
│
└── data/
    ├── scenarios.json            # 시나리오 블록 (standard_grounding 등)
    ├── templates.json            # NLG 폴백 템플릿
    └── guidance_feedback.jsonl   # 피드백 로그 (best_moments, worst_moments 포함)
```

### 3.2 Guidance API 계약

**POST /api/guidance/generate**

- **Request**: `GuidanceGenerateRequest`
  - `intake`: StrictIntakeInput (core_emotion, intensity, **face_data** 등)
  - `selected_theme_id`, `signal_degrade`, `confidence`, `cursor` (다음 Chunk 시)
- **Response**: `GuidanceOutputState`
  - `guidance_id`, `captions` (CaptionItem[]), `silence_ms`, `voice_profile`
  - `next_cursor` (다음 Chunk 요청 시 사용)

**POST /api/guidance/feedback**

- **Request**: `GuidanceFeedbackRequest`
  - `guidance_id`, `best_moments`, `best_moments_detail`
  - `worst_moments`, `worst_moments_detail`, `user_rating`, `session_id`, `theme_id` 등
- **Response**: `GuidanceFeedbackResponse` (ok, trace_id, saved_at)

### 3.3 백엔드 처리 흐름 (generate)

```
GuidanceGenerateRequest
  → decide_action(intake, selected_theme_id)  # policy_engine
  → render_scenario_chunk(action, intake, cursor, use_qwen=True)  # nlg_service
       │
       ├─ intake.face_data → face_desc (표정·호흡·심박 문구)
       ├─ resolve_arousal_level(intake) → hold_ms / silence_ms
       └─ Qwen(vLLM) 또는 로컬 템플릿 → CaptionItem[]
  → GuidanceOutputState(guidance_id, captions, next_cursor, ...)
```

## 4. 데이터 구조 요약

### 4.1 strictIntake → intake (백엔드로 전송)

- **출처**: EFTStrictPage에서 수집 후 `/meditation/theme` → `/meditation/session` → `/meditation/run`으로 state 전달.
- **guidanceService.toBackendIntake(intake, faceData)**:
  - `core_emotion`, `situation_context`, `automatic_thought`, `physical_sensation`, `behavioral_reaction`, `intensity`, `immediate_goal`, `available_time`
  - **face_data** (선택): MeditationRunPage에서 넣은 객체 (tension, tension_delta, baseline_tension, calibration_done, breath_rate, heart_rate, heart_rate_confidence 등)

### 4.2 face_data (설계 문서 §5)

- 프론트 `FaceData` 타입: dominant_emotion, intensity, tension, tension_filtered, tension_delta, baseline_tension, calibration_done, arousal, stress, quality, breath_rate, heart_rate, heart_rate_confidence, timestamp.
- 백엔드 `StrictIntakeInput.face_data`는 `Dict[str, Any]`로 동일 구조 수용.

### 4.3 Guidance 출력

- **captions**: `{ seq, text, hold_ms, type? }[]` — 자막 1~2개/Chunk.
- **next_cursor**: `{ scenario_id, next_block_index }` — 다음 Chunk 요청 시 필수.

## 5. 설계 문서 대비 매핑

| 설계 문서 개념 | 프론트엔드 | 백엔드 |

| 테마/시나리오 | MeditationThemePage, types/meditation (THEME_LIBRARY) | policy_engine, data/scenarios.json |

## 6. 요약

- **진입**: EFTStrictPage(감정 수집) → 명상 선택 → MeditationThemePage → MeditationSessionPage → **MeditationRunPage**.
- **프론트 핵심**: MeditationRunPage에서 **SignalProcessor(얼굴+Calibration+Luminance)**, **useBreathRate**, **rppg** 로 face_data 구성 후 **guidanceService** 로 Chunk 요청·피드백 전송.
- **백엔드 핵심**: **guidance_router** (`/api/guidance/generate`, `/api/guidance/feedback`) → **policy_engine** + **nlg_service** (face_data → face_desc, 호흡/심박 문구) + **guidance_feedback_service** (JSONL 저장).
