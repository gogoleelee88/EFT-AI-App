## 1. 현재 상태 분석

### 현재 구조

| 구분 | 파일 | 역할 |
|------|------|------|
| **프론트엔드** | `PlanDayPage.tsx` | 단일 페이지에서 Task + micro_steps를 한꺼번에 입력 |
| **백엔드 모델** | `Task` | task_id, title, est_minutes, priority, tags, energy_cost 등 |
| **백엔드 모델** | `DayPlan` | day_id, user_id, date, mode, items(JSON) |
| **백엔드 스키마** | `PlanItem` | task_id, task_title, est_minutes, planned_block_minutes, micro_steps[] |
| **백엔드 서비스** | `planner/service.py` | Task 자동 생성 + DayPlan 저장 |
| **백엔드 라우터** | `planner/router.py` | `POST /api/spec/plan/day`, `GET /api/spec/plan/day/{day_id}` |
| **라우트** | `routes.tsx` | `/plan/day` → PlanDayPage |

### 현재 한계점

1. **단일 페이지 구조**: 모든 입력이 하나의 긴 폼에 몰려 있음
2. **미세 행동 = 텍스트 직접 입력만 가능**: 이전 성공률 기반 추천 없음
3. **미션(인증) 시스템 없음**: 사진/장소/시간 인증 개념 자체가 없음
4. **알람 시스템 없음**: 설정한 시간에 알람을 보내는 기능 없음
5. **이전 할 일 재사용 UI 없음**: task_id를 숫자로 직접 입력해야 함

### 4.2 컴포넌트별 상세 설계

#### StepWizard.tsx — 스텝 프로그레스 바

```typescript
interface StepWizardProps {
  currentStep: 1 | 2 | 3 | 4;
  steps: { label: string; icon: string }[];
  onStepClick?: (step: number) => void;  // 이전 스텝만 클릭 가능
}
```

- 상단에 고정 표시되는 프로그레스 바
- 현재 단계 하이라이트, 완료된 단계는 체크마크
- 스텝: `① 할 일` → `② 미세 행동` → `③ 미션` → `④ 알람`

#### TaskInputStep.tsx — 1단계: 할 일 입력

```typescript
interface TaskInputStepProps {
  onNext: (task: SelectedTask) => void;
}

type SelectedTask = {
  source: "new" | "existing";
  task_id?: number;           // 기존 Task 선택 시
  task_title: string;
  est_minutes?: number;
  successRate?: number;        // 이전 Task 성공률
};
```

**UI 구성**:
- **새 할 일 입력**: 텍스트 입력 필드 (제목)
- **이전 할 일 목록**: `GET /api/spec/tasks/recent` → 성공률/마지막 사용일 표시
- **[다음]** 버튼 → 선택/입력한 Task 정보를 다음 스텝으로 전달

**API 필요**: `GET /api/spec/tasks/recent?user_id=xxx&limit=10`
→ 최근 사용한 Task 목록 + 각 Task의 성공률/마지막 사용일

#### MicroActionStep.tsx — 2단계: 미세 행동 선택

```typescript
interface MicroActionStepProps {
  task: SelectedTask;
  onNext: (action: SelectedMicroAction) => void;
  onBack: () => void;
}

type SelectedMicroAction = {
  source: "history" | "ai_recommendation" | "user_custom";
  name: string;                // "한 문제만 풀기"
  description?: string;        // "1번 문제 풀이 시작"
  start_trigger?: string;      // "문제에 동그라미 치기"
  est_minutes?: number;        // 예상 시간
  micro_action_id?: number;    // 기존 미세행동 재사용 시
  previousMissions?: Mission[]; // "다시 하기" 시 이전 미션 정보 전달
};
```

**UI 구성**:
- **상단 섹션**: `🔄 내가 자주 하는 방법`
  - 해당 Task에서 이전에 사용한 미세행동 목록
  - 각 항목: 이름, 성공률 (N/M회), 마지막 사용일, [다시 하기] 버튼
- **하단 섹션**: `✨ 새로운 방법 시도`
  - AI 추천 미세행동 3개 (Task 제목 기반)
  - 각 항목: 이름, 예상 시간, [선택] 버튼
- **맨 아래**: `✏️ 직접 입력` 텍스트 필드

**분기 처리**:
- **[다시 하기]** 선택 → 3단계로 이동 시 `previousMissions` 포함 (이전 미션 설정 불러오기)
- **[선택] / 직접 입력** → 3단계로 이동 시 `previousMissions = undefined` (새 미션 설정)

**API 필요**:
- `GET /api/spec/micro-actions?task_id=xxx` → 해당 Task의 이전 미세행동 이력
- `POST /api/spec/micro-actions/recommend` → AI 기반 미세행동 추천

#### MissionSettingStep.tsx — 3단계: 미션 설정

```typescript
interface MissionSettingStepProps {
  task: SelectedTask;
  microAction: SelectedMicroAction;
  onNext: (missions: MissionConfig[]) => void;
  onBack: () => void;
}

type MissionConfig = {
  type: "photo" | "location" | "time_check";
  enabled: boolean;
  config: PhotoMissionConfig | LocationMissionConfig | TimeMissionConfig;
};
```

**케이스 A — "다시 하기" 선택 시** (이전 미션 설정 존재):
- `💾 이전 설정 불러오기` 헤더 표시
- 각 미션별 `[유지]` / `[수정]` 토글
- `[이전 설정 그대로 사용]` 빠른 저장 버튼
- `[수정하고 저장]` 수정 후 저장 버튼

**케이스 B — "새로운 방법" 선택 시** (새 미션 설정):
- `🆕 처음 시도하는 방법이에요` 안내 텍스트
- `🤖 AI 추천 미션` 섹션 → 자동으로 추천 미션 표시
- 각 미션 토글 (☑/□) + 상세 설정 펼치기
- `[AI 추천대로 전부]` 원클릭 버튼
- `[직접 커스텀]` 개별 설정 버튼

**미션 타입 3종**:

1. **📸 사진 인증** (MissionPhotoConfig):
   - **AI 다중 추천** (ChatGPT API 기반, 탭하면 선택):
     - 옵션 1: 손글씨 + 펜 → 검증: OCR(공식 텍스트) + 펜 검출
     - 옵션 2: 문제집 표지 → 검증: 책 객체 검출
     - 옵션 3: 노트 + 교재 → 검증: 다중 객체 검출
   - **직접 설정하기**: 텍스트 입력으로 커스텀 요구사항 정의
   - **예시 사진 보기**: PhotoExampleGallery 모달 → 이미지 갤러리 표시
   - 각 추천 옵션에 **검증 방법이 함께 표시**됨

2. **📍 장소 인증** (MissionLocationConfig):
   - **자주 가는 장소 목록**: 장소명, 주소/Wi-Fi, 성공률(N/M회), 마지막 사용일
   - **[선택]** 버튼으로 즉시 선택
   - **+ 새 장소 등록하기** → PlaceRegistrationForm 모달 열기
     - 장소 이름 입력
     - 위치 확인 방법 (복수 선택 가능):
       - ☑ GPS: 현재 위치 저장 + 정확도 표시 (±30m)
       - ☑ Wi-Fi: 감지된 네트워크 목록에서 선택
       - □ Bluetooth Beacon: 비콘 검색
   - **○ 장소 상관없음** (위치 인증 건너뛰기)

3. **⏰ 시간 확인** (MissionTimeConfig):
   - **시간 선택**: [시] : [분] 입력
   - **확인 방법** (복수 선택 가능):
     - ☑ 화면 캡처 인증 → 작업 중인 화면 자동 확인:
       - ☑ 특정 앱 실행 중 (예: PDF 뷰어, 문제집 앱)
       - ☑ 특정 파일 열림 (예: 수학_문제집.pdf)
       - □ 파일 수정 시간 확인 (최근 N분 내 수정됨)
     - □ 사진 인증 → 설정한 시간에 직접 사진 촬영
   - **알림 방식**: ○ 조용히 확인 (백그라운드) / ● 알림 띄우기 (푸시)

### 4.3 위저드 상태 관리 — usePlanWizard.ts

            {"role": "user", "content": user_msg}
        ],
        response_format={"type": "json_object"},
        temperature=0.7,
        max_tokens=800,
    )
    # JSON 파싱 후 반환
    ...

## 9. 미션 조합 모드 및 알람 해제 로직

### 9.1 미션 조합 모드 3종

| 모드 | 이름 | 조건 | 사용 예시 |
|------|------|------|-----------|
| **strict** | 엄격 모드 | 활성화된 미션 **전부** 통과해야 알람 해제 | 사진 + 장소 + 시간 모두 필요 |
| **basic** | 기본 모드 | 활성화된 미션 중 **사진 미션**만 통과하면 해제 | 사진만 찍으면 OK |
| **flexible** | 유연 모드 | 활성화된 미션 중 **아무 1개**만 통과하면 해제 | 장소 도착만으로 OK |

### 9.2 조합 예시 (원본 스펙 반영)

```
조합 1: 엄격 모드 (strict)
  미션1 ✅ 사진 (손글씨 + 펜)
  미션2 ✅ 장소 (스터디카페)
  미션3 ✅ 시간 (19:30 재확인)
  → 3개 모두 통과해야 알람 해제

조합 2: 기본 모드 (basic)
  미션1 ✅ 사진 (문제집 표지)
  미션2 □ 장소 (선택 안 함)
  미션3 □ 시간 (선택 안 함)
  → 사진만 통과하면 알람 해제

조합 3: 유연 모드 (flexible)
  미션1 □ 사진 (선택 안 함)
  미션2 ✅ 장소 (헬스장 도착)
  미션3 □ 시간 (선택 안 함)
  → 장소 도착만으로 알람 해제
```

### 9.3 알람 해제 판정 로직 (백엔드)

```python
def check_alarm_dismissal(
    missions: list[MissionResult],
    combination_mode: str,  # "strict" | "basic" | "flexible"
) -> bool:
    """미션 결과 기반으로 알람 해제 여부 판정"""
    enabled_missions = [m for m in missions if m.enabled]
    passed_missions = [m for m in enabled_missions if m.passed]

    if combination_mode == "strict":
        # 모든 활성화 미션 통과 필요
        return len(passed_missions) == len(enabled_missions)

    elif combination_mode == "basic":
        # 사진 미션 통과 필요 (없으면 아무 1개)
        photo_missions = [m for m in enabled_missions if m.type == "photo"]
        if photo_missions:
            return all(m.passed for m in photo_missions)
        return len(passed_missions) >= 1

    elif combination_mode == "flexible":
        # 아무 1개만 통과
        return len(passed_missions) >= 1

    return False
```

## 11. 기술적 결정 사항

### 11.1 PlanDayPage 리팩토링 전략

| 선택지 | 장점 | 단점 |
|--------|------|------|
| **A) 기존 페이지 내부에 스텝 분기** | 라우트 변경 없음, URL 깔끔 | 컴포넌트 복잡도 증가 |
| B) 각 스텝을 별도 라우트로 분리 | 브라우저 뒤로가기 자연스러움 | 상태 전달 복잡 |

→ **A 선택 권장**: 기존 `/plan/day` URL 유지, 내부에서 `step` state로 분기.
  `usePlanWizard` 훅에서 전체 상태를 관리하므로 컴포넌트 간 데이터 전달이 깔끔함.

### 11.2 미션 검증(인증) 처리 위치

| 선택지 | 설명 |
|--------|------|
| **Phase 1: 설정만 저장** | 미션 "설정"만 저장하고, 실제 검증(사진 OCR, GPS 확인 등)은 추후 구현 |
| Phase 2: 검증 로직 추가 | 사진 업로드 → OCR/객체 검출, GPS 확인 등 |

→ **Phase 1부터 시작 권장**: 먼저 UI 플로우와 데이터 저장을 완성하고,
  실제 인증 검증 로직(사진 분석, GPS 매칭 등)은 별도 Phase로 분리.

### 11.3 AI 추천 엔진 (미세행동/미션)

| 선택지 | 설명 |
|--------|------|
| A) 규칙 기반 + 템플릿 | Task 제목 키워드 매칭으로 미리 정의된 추천 반환 (빠르고 안정적) |
| B) vLLM/Qwen (로컬) | 기존 서버 AI에게 추천 생성 (추가 비용 없음, 품질 불안정) |
| **C) ChatGPT API (확정)** | OpenAI API로 구조화된 추천 생성 (안정적, JSON mode 지원) |
| D) 하이브리드 | ChatGPT 우선, 실패 시 규칙 기반 폴백 |

→ **D 하이브리드 확정**:
  - 메인 엔진: **ChatGPT API (gpt-4o-mini)** → JSON 구조화된 추천 생성
  - 폴백: 규칙 기반 템플릿 → API 장애/키 미설정 시 즉시 반환
  - 기존 vLLM/Qwen은 **대화형 AI 상담 전용**으로 유지
  - `일정관리 및 재진입.ini`의 GraphRAG/Bandit 엔진과 향후 연동 예정
