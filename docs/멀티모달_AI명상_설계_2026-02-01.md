# 멀티모달 기반 사용자 맞춤형 AI 명상 서비스 설계 (2026-02-01)

**문서 상태**: 제작된 기능 기준으로 최신화됨 (구현 완료 항목 표시).

## 1. 비전

**"실시간으로 사용자 감정을 읽고, AI가 그에 맞춰 명상을 가이드하는 서비스"**

- **멀티모달**: 얼굴(표정), 호흡(오디오), rPPG(심박) — **3종 모두 연동 완료**
- **감정 추정**: tension, eyeOpen, perclos, breathRate, heartRate → valence, arousal, stress
- **AI 가이드**: Guidance API가 face_data를 받아 자막/NLG 실시간 맞춤화
- **Context-aware**: Calibration(baseline_tension, tension_delta), Kalman 필터, Luminance(Auto-Illumination) 적용

## 4. 멀티모달 → 감정 매핑

### 4.1 FaceSignals → face_data

| FaceSignals | face_data 필드 | 설명 | 구현 |
|-------------|----------------|------|------|
| tension (0~1) | tension, stress, tension_filtered, tension_delta | Kalman 필터 후, Calibration 시 Delta 기준 | ✅ |
| eyeOpen (0~1) | - | 눈 감김 정도 | ✅ |
| perclos (0~1) | - | 졸음/이완 지표 | ✅ |
| head.yaw, pitch | - | 집중도 (큰 각도 = 산만) | ✅ |
| quality (0~1) | quality | 신호 품질 | ✅ |

**추정 규칙 (AS-IS, Calibration 미완료 시)**:
```
tension > 0.6  → dominant_emotion: "긴장", arousal: 0.8
tension 0.4~0.6 → dominant_emotion: "불안", arousal: 0.6
tension < 0.4, perclos > 0.5 → dominant_emotion: "이완", arousal: 0.3
```

**Context-aware (TO-BE, Calibration 완료 시)** — ✅ 구현됨:
```
tension_delta > 0.2  → dominant_emotion: "긴장", arousal: 0.8
tension_delta > 0.1  → dominant_emotion: "불안", arousal: 0.6
tension_delta < -0.1, perclos > 0.5 → "이완", arousal: 0.3
그 외 → "보통" / "집중"
```

### 4.2 breathRate (호흡/분) → arousal

| breathRate | 해석 | arousal 보정 |
|------------|------|--------------|
| < 8 | 얕은 호흡, 긴장 | +0.2 |
| 8~14 | 정상 | 0 |
| > 20 | 빠른 호흡, 불안 | +0.3 |

### 4.3 heartRate (심박, rPPG) → arousal / stress

| heartRate (BPM) | 해석 | arousal 보정 |
|-----------------|------|--------------|
| < 60 | 이완/저각성 | -0.1 |
| 60~80 | 정상 | 0 |
| 80~100 | 약간 긴장 | +0.2 |
| > 100 | 불안/스트레스 | +0.3 |

**구현 상태**: rPPG 파이프라인 구현 완료. 녹색 채널 시계열 → detrend → DFT(0.7~4 Hz) → BPM·confidence. confidence < 0.4이면 NLG에 미반영.

## 5. face_data 스키마 (현재 구현)

```typescript
interface FaceData {
  dominant_emotion?: string;   // "긴장" | "불안" | "이완" | "집중" | "보통" 등
  intensity?: number;          // 0~1
  tension?: number;            // 0~1 (원본)
  tension_filtered?: number;    // Kalman 필터 후 (Context-aware)
  tension_delta?: number;      // current - baseline (Calibration 완료 시)
  baseline_tension?: number;   // Calibration 기준값
  calibration_done?: boolean;  // Delta 기준 사용 여부
  arousal?: number;            // 0~1 (각성 수준)
  stress?: number;             // 0~1
  quality?: number;            // 0~1 (신호 품질)
  breath_rate?: number;        // 호흡/분 ✅
  heart_rate?: number;         // 심박 BPM (rPPG) ✅
  heart_rate_confidence?: number;  // 0~1, rPPG 신뢰도 ✅
  timestamp?: number;          // ms
}
```

백엔드 `StrictIntakeInput.face_data`는 `Dict[str, Any]`이므로 위 구조 그대로 전송 가능.

## 6. 구현 단계

### Phase 1: Face 데이터 수집 + Guidance API 연동 — ✅ 완료

1. **MeditationRunPage에 카메라 추가** — ✅
   - `requestMediaOnce`로 스트림 획득, 숨김 video/canvas
   - `initFaceLandmarker` + `analyzeFace` 주기 호출 (400ms)

2. **FaceSignals → face_data 변환** — ✅
   - `faceDataMapper.faceSignalsToFaceData` (Calibration 시 tension_delta 기준)
   - `guidanceService.toBackendIntake`에 `face_data` 포함

3. **Chunk 요청 시 face_data 포함** — ✅
   - 첫 Chunk: strictIntake + (null 또는 초기 face_data)
   - 다음 Chunk: **최신 face_data** (SignalProcessor 처리 결과) 포함

4. **백엔드 NLG** — ✅
   - `intake.face_data` → `face_desc` (표정/강도, 호흡, 심박 문구 반영)

### Phase 2: 호흡 데이터 연동 — ✅ 완료

- `useBreathRate(mediaStream, isRunning)` 훅 (마이크 RMS 피크 → breaths/min)
- face_data에 `breath_rate` 추가, arousal 보정
- NLG: "호흡: 빠름/정상/느림" 반영

### Phase 3: 실시간 적응 빈도 — ✅ 적용

- face 샘플링 400ms 고정 (필요 시 tension/breath에 따라 300/500 전환 가능)
- Chunk 경계마다 최신 face_data 전송

### Phase 4: rPPG 심박 추정 — ✅ 완료

| 파일/함수 | 상태 |
|-----------|------|
| `extractHeartRate(frames, fps)` | 녹색 채널 → detrend → DFT(0.7~4 Hz) → BPM·confidence |
| `getLuminanceFromVideo` | SignalProcessor에서 별도 (Auto-Illumination) |
| `getForeheadROI()`, `extractROIPixels()`, `averageRGB()` | ROI/유틸 유지 |
| `calculateHRV()` | placeholder (선택) |

- MeditationRunPage: 10Hz 프레임 버퍼(중앙 40×40 ROI) → 10초마다 `extractHeartRate` 호출
- face_data에 `heart_rate`, `heart_rate_confidence` 추가, confidence < 0.4 시 NLG 미반영

### Context-aware (Calibration + Luminance) — ✅ 완료

- **SignalProcessor** (`signals/SignalProcessor.ts`): KalmanFilter1D(tension), Calibration(5~10초 → baseline_tension, tension_delta), `getLuminanceFromVideo`, `isLowLight`
- **Calibration Phase UI**: "잠시 편하게 있어 주세요 (캘리브레이션 중…)" 배너
- **Auto-Illumination**: luminance < 0.25 시 배경 미색(`#faf8f5`) 전환

## 7. 플로우 (현재 구현 기준)

```
1. 사용자: 감정 입력 (SlideIntake) → 명상 경로 → /meditation/theme → 테마 선택 → /meditation/run
2. MeditationRunPage 진입:
   - strictIntake + selected_theme_id 로 첫 /api/guidance/generate (face_data: null 가능)
   - 첫 청크 로드 후 카메라 권한 → requestMediaOnce, FaceLandmarker 초기화
3. Calibration Phase (5~10초, 기본 8초):
   - "잠시 편하게 있어 주세요 (캘리브레이션 중…)" 배너 표시
   - SignalProcessor: Kalman(tension) + baseline_tension 수집 → calibration_done 후 tension_delta 사용
4. 자막 표시 중:
   - 400ms마다 analyzeFace → SignalProcessor.process → faceSignalsToFaceData → face_data 갱신
   - useBreathRate(마이크), rPPG 10Hz 버퍼 → 10초마다 heart_rate 갱신
   - Chunk 소진 시 next_cursor + **최신 face_data** 로 재요청
5. AI: face_data(표정·호흡·심박·tension_delta) 반영 맞춤 멘트
6. 긴급: "🆘 긴급 도움" 버튼 항상 노출; tension_delta>0.2 또는 breathRate>25 지속 시 자동 제안 배너
7. 만족도: "이 순간 좋았어요/별로였어요" → best_moments / worst_moments → /api/guidance/feedback
8. 종료 시 피드백 모달(별점, best/worst_moments) → 제출 후 대시보드
```

## 9. 추가·최신 방법 (2024–2025 기준)

현재 설계(표정, 호흡, rPPG) 외에 더 정확하고 최신적인 수집·추정 방법들입니다.

### 9.1 카메라 기반 (웨어러블 불필요)

| 방법 | 설명 | 정확도/특징 | 적용 난이도 |
|------|------|-------------|-------------|
| **Face Mesh v2 Blendshapes** | MediaPipe v2 52개 블렌드쉐입 → 미세 표정 | 478 랜드마크, 아이리스 지원 | 중 |
| **얼굴 랜드마크(눈썹·입술)** | 눈썹/입술 움직임 → 스트레스 상관 | 2024 연구: 웹캠만으로 84%+ 스트레스 검출 | 낮음 |
| **rPPG + skin color amplification** | 피부 색 증폭 → 심박 추정 | 2024: 평균 오차 ~5.79 BPM | 중 |
| **rPPG ML/DL** | 머신러닝·딥러닝 기반 rPPG | 접촉식과 유사 수준 (일부 조건) | 높음 |

**2024 웹캠 전용 스트레스 검출 (웨어러블 불필요)**  
- 얼굴 감정(96%+) + rPPG(피부 색 증폭) + 얼굴 랜드마크 융합  
- 웹 브라우저에서 실행 가능, 추가 하드웨어 없음  

### 9.2 음성·발화 기반

| 방법 | 설명 | 특징 | 적용 난이도 |
|------|------|------|-------------|
| **Prosodic features** | F0, jitter, HNR, 말 속도 | 생리적 스트레스와 연관 | 중 |
| **Speaker embedding** | 화자별 특성 + 음향 특징 | 3~5초 오디오, 개인차 보완 | 중 |
| **자기보고 + 음성** | 사용자 발화 시점 음성 분석 | 말하기 기반 명상에 적합 | 중 |

명상 중에는 대화가 거의 없으므로, **호흡/숨소리** 분석이 더 적합합니다.

### 9.3 Valence–Arousal 모델

| 차원 | 의미 | 멀티모달 매핑 |
|------|------|---------------|
| **Valence** | 쾌·불쾌 (-1 ~ +1) | 표정(미소/우울), 음성 톤 |
| **Arousal** | 각성 수준 (0 ~ 1) | tension, 심박, 호흡률 |

2024–2025 연구들은 **valence–arousal** 연속 추정을 표준으로 사용합니다.

### 9.4 웨어러블·외부 API (선택)

| 소스 | 데이터 | 특징 | 적용 난이도 |
|------|--------|------|-------------|

| **Apple Health / Google Fit** | HRV, 심박 | 사용자 동의·OAuth 필요 | 중 |

## 10. 명상 중 응급 대처 (Emergency Handling)

명상 중 갑작스런 불안, 패닉, 힘든 상황이 생겼을 때 즉시 대처할 수 있는 기능입니다.

### 10.1 긴급 버튼 (SOS)

| 항목 | 설명 |
|------|------|
| **위치** | 명상 화면 상단 또는 플로팅 버튼 (항상 노출) |
| **라벨** | "긴급 도움" / "지금 힘들어요" / SOS 아이콘 |
| **동작** | 탭 시 즉시 응급 대처 화면으로 전환 |

### 10.2 응급 대처 화면 (Emergency Mode)

**1단계: 즉시 진정 (박스 호흡 / 네이비씰 호흡법)**

- **박스 호흡 (Box Breathing)**: 4-4-4-4 패턴
  - 4초 들이쉬기 → 4초 멈춤 → 4초 내쉬기 → 4초 멈춤
  - 교감신경 안정화, 패닉 반응 완화
  - 최소 5분 권장 (3~5회 사이클로도 즉시 효과)
- **시각 가이드**: ARBoxBreathingPage 또는 단순 타이머 (4초 카운트)

### 10.3 멀티모달 기반 자동 감지 — ✅ 구현됨

| 조건 | 동작 | 구현 |
