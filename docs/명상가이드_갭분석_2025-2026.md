# 명상 가이드 서비스 갭 분석 (2025–2026 기준)

**문서 성격**: 현재 구현된 명상 가이드 서비스와 2025–2026년 연구·기술 동향을 비교한 **갭 분석**.  
**참조**: `명상가이드_서비스_설계명세_구현기준.md`(현재 구현), 웹 검색 기반 최신 논문·기술.

---

## 1. 개요

### 1.1 목적

- **현재 서비스**: 규칙 기반 정책 + LLM NLG + 멀티모달(얼굴·호흡·rPPG) + TTS 스타일(쿨다운/히스테리시스) + 피드백 JSONL.
- **갭 분석**: 영역별로 “최신 연구·기술 대비 무엇이 보수적이고, 무엇이 이미 잘 맞는지” 정리.

### 1.2 정리 방식

- **현재**: 구현 명세 기준 요약.
- **최신(2025–2026)**: 논문·기술 검색 결과 요약.
- **갭**: 보수적(업그레이드 여지) / 적정(유지 권장) / 강점(이미 잘 맞음).

## 2. 멀티모달 입력 (얼굴·호흡·심박)

### 2.1 현재 구현

| 항목 | 내용 |
|------|------|
| 얼굴 | MediaPipe Face Landmark, tension/tension_delta, Kalman 필터, Calibration(baseline), quality |
| 호흡 | 마이크 기반 breath_rate (useBreathRate) |
| 심박 | rPPG(녹색 채널·DFT) → heart_rate, heart_rate_confidence (confidence &lt; 0.4 시 NLG 미반영) |
| 감정 표현 | tension_delta·perclos 기반 규칙(긴장/이완/졸음) + dominant_emotion, arousal 추정 |

### 2.2 최신 동향 (2025–2026)

| 출처 | 내용 |
|------|------|
| rPPG 2025 | 얼굴 영상 기반 **HRV(Heart Rate Variability)** 추정 검증; 스트레스·자율신경 균형 비접촉 측정. |
| rPPG 2025 | 3D CNN + differential frame fusion, temporal shift 등 **딥러닝 rPPG**로 복잡 환경에서 BVP 추출 성능 향상. |
| Nature 2025 | **EmpathicSchool** 등 멀티모달 스트레스 데이터셋(얼굴 + HR, EDA, 피부온도)으로 스트레스 검출 AI 개선. |
| 2025 MAVEN | **Valence–Arousal** 다중모달(영상·음성·텍스트) + cross-modal attention, Aff-Wild2 등에서 성능 향상. |

### 2.3 갭

| 구분 | 판단 | 설명 |
|------|------|------|
| rPPG BPM만 사용 | **보수적** | HRV 지표 미사용. 2025 연구는 rPPG 기반 HRV·스트레스까지 활용. |
| 규칙 기반 감정 | **보수적** | Valence–Arousal 연속 추정·다중모달 융합 대비, 규칙(tension_delta/perclos) 위주. |
| Kalman + Calibration | **적정** | 신호 안정화·baseline 제거는 현재에도 타당. |
| quality / confidence 게이팅 | **강점** | 품질·신뢰도 낮을 때 미반영하는 설계는 연구 권장과 부합. |

## 3. 감정 컴퓨팅·적응형 지원 (Affective Computing)

### 3.1 현재 구현

| 항목 | 내용 |
|------|------|
| 적응 대상 | NLG(face_desc·arousal → hold_ms/silence_ms), TTS(tts_instruction, tts_speed) |
| 반영 경로 | face_data → PolicyEngine은 사용 안 함; NLG·VoiceStyleManager만 사용 |
| 상태 제어 | TTS: 쿨다운 15초, Calm 히스테리시스(진입 3초/이탈 8초), 품질 게이팅 |

### 3.2 최신 동향 (2025–2026)

| 출처 | 내용 |
|------|------|
| Frontiers 2025 | **Emotionally adaptive support**: 감정 인식·감성 분석·생리 신호를 결합한 DMHI, 참여·만족도 개선. 알고리즘 편향·프라이버시·윤리 설계 이슈 부각. |
| SciDirect 2024–2025 | **Closed-loop neurofeedback**: fMRI/EEG 실시간 피드백으로 명상 품질·참여·용량 맞춤 조절. |
| 2025 RCT | **Closed-loop mindfulness**: 앱 + 정량 피드백 + **적응형 세션 길이**로 스트레스 감소 검증 프로토콜. |

### 3.3 갭

| 구분 | 판단 | 설명 |
|------|------|------|
| 시나리오/테마 고정 | **보수적** | 감정 상태에 따라 “어떤 시나리오/테마를 할지” 실시간 전환은 없음. |
| hold/silence만 적응 | **적정** | arousal 기반 타이밍 조절은 적응형 지원에 해당. |
| TTS 톤·속도 적응 | **강점** | 감정에 따른 음성 적응은 2025 감정 적응형 DMHI 흐름과 방향 일치. |
| Closed-loop neurofeedback | **보수적** | EEG/fMRI 기반 실시간 뇌 피드백은 미사용(비용·장비 한계). |

## 4. NLG·LLM (자막 생성)

### 4.1 현재 구현

| 항목 | 내용 |
|------|------|
| 방식 | 시나리오 블록(JSON) + Qwen(vLLM) 각색, 최대 2줄/Chunk, base_text/adapt_instruction |
| 입력 | face_desc(표정·호흡·심박 문구), core_emotion, situation_context, automatic_thought, guide_tone |
| 안전 | DENYLIST_PHRASES, task_atom 포함 검사, 2줄 초과 시 로컬 폴백 |

### 4.2 최신 동향 (2025–2026)

| 출처 | 내용 |
|------|------|
| MDPI 2025 | **LLM 기반 메타버스 명상**: 동적 시나리오 생성, 호흡 동기화 피드백. |
| JMIR 2025 | **GenAI 정신건강 개입**: 안전성·UX 탐색적 RCT; “치료사” 광고 금지, 목적 특화 LLM 연구 필요 제기. |
| FDA 2025 | **LLM 치료 사용 평가**: 위기 대응 부족, 망상·자해 유도 위험, 전용 안전 프로토콜 필요. |

### 4.3 갭

| 구분 | 판단 | 설명 |
|------|------|------|
| 시나리오 뼈대 고정 + 각색만 | **적정** | 완전 자유 생성보다 안전·일관성 측면에서 유리. |
| 금칙어·task_atom 검사 | **강점** | 진단/명령 표현 차단은 2025 안전 권고와 부합. |
| 위기/자해 전용 프로토콜 | **보수적** | 2025 연구는 위기 감지·대응·리소스 안내 등 전용 플로우 권장; 현재는 별도 명시 없음. |

## 5. TTS·음성 (CosyVoice, Hybrid Pacing)

### 5.1 현재 구현

| 항목 | 내용 |
|------|------|
| 출력 | tts_instruction(문자열), tts_speed(배율). 실제 합성은 클라이언트. |
| 스타일 | Neutral / Calm(soothing, 0.8) / Awake(energetic, 1.1). R1~R4(쿨다운, 히스테리시스, 품질 게이팅, MVP 톤만). |

### 5.2 최신 동향 (2025–2026)

| 출처 | 내용 |
|------|------|
| CosyVoice 3 (2025.5) | **감정 인식 통합 토크나이저**, 세밀한 감정 제어, 다국어·방언 zero-shot, 1M시간 규모, 1.5B 파라미터. |
| CosyVoice 2 (2024) | 스트리밍, **감정·억양 제어**, 150ms 첫 패킷, MOS 5.53. |

### 5.3 갭

| 구분 | 판단 | 설명 |
|------|------|------|
| instruction + speed만 사용 | **보수적** | CosyVoice 2/3는 더 세밀한 감정·억양 제어 지원; MVP는 톤·속도만 사용. |
| 쿨다운·히스테리시스 | **강점** | 채터링 방지·UX 안정성은 실서비스에 적합. |
| 품질 게이팅 후 Neutral | **강점** | 신뢰도 낮을 때 과한 연기 방지는 연구 권장과 맞음. |

## 9. 요약 표

| 영역 | 현재 | 최신(2025–2026) | 갭 요약 |
|------|------|------------------|---------|
| 멀티모달 | 얼굴(tension/rPPG BPM)·호흡·규칙 감정 | HRV·딥 rPPG·Valence–Arousal·다중모달 융합 | HRV·연속 감정·딥 rPPG 미사용 |
| 감정 적응 | NLG 타이밍 + TTS 톤/속도 | 감정 적응형 지원·closed-loop 적응 | 시나리오 전환·세션 길이 적응 없음 |

| 정책 | 규칙 테마→시나리오 | LLM 동적 시나리오·적응형 용량 | 규칙 기반 유지 |
| 안전 | 금칙어·진단/명령 차단 | READI·위기 대응·전문가 협업 | 위기/자해 전용 백엔드 없음 |
| Closed-loop | TTS·hold/silence만 | Neurofeedback·적응형 세션 길이 | 세션 길이·EEG 미적용 |

## 10. 우선 적용할 개선 항목 제안

갭 분석을 바탕으로 **효과 대비 도입 난이도**를 고려해, 우선 적용을 제안할 영역만 짧게 정리한다.

### 10.1 위기 대응 (우선순위: 높음)

| 항목 | 내용 | 비고 |
|------|------|------|
| 위기/자해 전용 백엔드 플로우 | NLG 요청 전·후에 **위험 키워드 검사** 또는 전용 **crisis_check** 단계 추가. 감지 시 고정 안내문(1393·생명의전화 등) + `meta.crisis_detected` 등 플래그 반환. | 2025 FDA·Stanford 권고와 부합. 프론트는 이미 긴급 버튼·박스 호흡 있음. |
| decision_trace에 안전 사유 | 위기 감지 시 trace에 `"Crisis: keyword detected, returning safe message"` 등 기록. | 감사·디버깅 용이. |

- **범위**: Guidance generate 진입부 또는 NLG 호출 전 미들웨어 1곳에서 처리하면 됨. 기존 금칙어 확장 또는 전용 리스트 사용.

### 10.2 rPPG·HRV (우선순위: 중)

| 항목 | 내용 | 비고 |
|------|------|------|
| face_data에 HRV 지표 추가 | rPPG 파이프라인에서 **RR 간격 또는 SDNN 등 HRV 관련 지표** 1~2개 산출 후 face_data에 포함. | 2025 연구는 rPPG 기반 HRV·스트레스 검증. BPM만 쓰는 현재 대비 스트레스/이완 해석 보강. |
| NLG/VoiceStyleManager에서 HRV 활용 | HRV 저하(스트레스) 시 face_desc에 "심박 변이 낮음" 등 문구 추가, 또는 TTS Calm 모드 진입 보조 조건으로 사용(선택). | 기존 tension_delta·perclos와 병행. |

- **범위**: 프론트 rPPG 파이프라인 확장 + face_data 스키마·백엔드 FaceData(voice_schema)에 필드 추가. 백엔드는 선택적으로만 사용해도 됨.

### 10.3 TTS 고도화 (우선순위: 중)

| 항목 | 내용 | 비고 |
|------|------|------|
| CosyVoice 2/3 세밀 제어 연동 | 현재 tts_instruction 문자열 외에 **감정 라벨·강도** 등 CosyVoice가 지원하는 파라미터가 있으면, TTSConfig 또는 응답 메타에 추가해 클라이언트가 전달. | MVP는 톤·속도만 사용 중; 점진적 확장. |
| R4 확장(선택) | "속삭임·떨림" 등 연기는 서비스 정책이 허용할 때만, **별도 플래그(예: allow_acting)** 로 제어. 기본은 현재처럼 톤·속도만. | UX 일관성 유지하면서 실험 가능. |

- **범위**: VoiceStyleManager 출력 스키마 확장 + 클라이언트 TTS 호출부만 수정. 기존 R1~R3 유지.

### 10.4 기타 (참고)

|------|----------|------|
